## 1. Ган саваа огтлох (Rod Cutting, CLRS 14.1)

`python/src/cut_rod.py`, `java/.../CutRod.java`.

**Бодлого.** n урттай саваа, i урттай хэсгийн үнэ pᵢ. Огтлолтыг сонгож орлогыг хамгийн их болгоно.

**Дахин дуудах томьёо.** Эхний хэсгийн урт i-г сонговол үлдсэн n − i урттай саваа нь мөн ижил
бодлого: r₀ = 0, **r_n = max₁≤ᵢ≤ₙ (pᵢ + r_{n−i})**.

Энгийн дахин дуудалт (Cut-Rod) ижил r_j-г олон дахин бодох тул T(n) = 1 + Σⱼ₌₀^(n−1) T(j) = **2ⁿ**.
Bottom-Up хувилбар r₁, r₂, …, r_n-г дарааллаар нь нэг удаа бодно.

### 1.1 Дотоод давталтын тоо = n(n+1)/2
j = 1, …, n бүрд дотоод давталт i = 1, …, j буюу j удаа эргэнэ:

  Σⱼ₌₁ⁿ j = n(n+1)/2 = **Θ(n²)**.

`rod_01.tsv` (n = 10 → 55, n = 15 → 120) болон n = 1, 2, 3, 5, 10 дээр хоёр хэлэнд шалгав.
Тоо нь үнийн утгаас үл хамаарна.

### 1.2 Огтлолтыг сэргээх (Extended-Bottom-Up-Cut-Rod)
s[j]-д j урттай савааны **эхний хэсгийн** оновчтой уртыг хадгалж, n-ээс эхлэн s-ийг дагаж хэсгүүдийг
гаргана. Жишээ нь CLRS-ийн үнэд (n = 10) хариу 30, хэсэг [10] буюу огтлохгүй байх нь оновчтой.
`rod_cuts_01.tsv` дээр хэсгүүдийн нийлбэр n, үнийн нийлбэр хамгийн их орлоготой тэнцүү байгааг
шалгав. Олон оновчтой хариу байж болох тул тест нь тодорхой хэсэглэлийг биш, хүчинтэй байдлыг
шалгадаг.

## 2. Матрицуудын цуваа үржвэр (Matrix-Chain Multiplication, CLRS 14.2)

`python/src/matrix_chain.py`, `java/.../MatrixChain.java`.

**Бодлого.** A₁A₂…A_n (Aᵢ нь p_{i−1} × pᵢ) үржвэрт хаалтыг тавьж скаляр үржүүлэлтийн тоог хамгийн
бага болгоно. Хаалт тавих аргын тоо Каталаны тоо буюу Ω(4ⁿ/n^1.5) тул бүгдийг шалгах боломжгүй.

**Дахин дуудах томьёо.** m[i][j] нь Aᵢ…A_j-ийн хамгийн бага өртөг:

  m[i][i] = 0,  **m[i][j] = min_{i≤k<j} (m[i][k] + m[k+1][j] + p_{i−1}·p_k·p_j)**.

Хүснэгтийг гинжийн уртаар (2, 3, …, n) бөглөж, s[i][j]-д хамгийн сүүлд хуваах k-г хадгална.
Print-Optimal-Parens нь s-ийг дагаж хаалтыг байгуулна.

**Шинжилгээ.** (i, j) хос Θ(n²), тус бүрд k-гийн давталт O(n) тул **Θ(n³)** хугацаа,
m ба s хүснэгт **Θ(n²)** санах ой.

Хаалтын байрлал үржвэрийн утгыг өөрчлөхгүй ч ажлын хэмжээг хэд дахин өөрчилж болно. Тест нь

## 3. Хамгийн урт ерөнхий дэд дараалал (LCS, CLRS 14.4)

`python/src/lcs.py`, `python/src/lcs_diff.py`, `java/.../Lcs.java`.

**Дахин дуудах томьёо.** c[i][j] нь X[1..i], Y[1..j]-ийн LCS-ийн урт:
c[i][0] = c[0][j] = 0;  xᵢ = yⱼ бол c[i][j] = c[i−1][j−1] + 1;  эс бөгөөс
c[i][j] = max(c[i−1][j], c[i][j−1]).

**Шинжилгээ.** Хүснэгт (m+1)(n+1) нүдтэй, нүд бүр Θ(1) тул **Θ(mn)** хугацаа. Уртыг л олоход
хүснэгтийн зөвхөн өмнөх мөр хэрэгтэй тул `lcs_length` хоёр мөр хадгалж **Θ(n)** санах ой хэрэглэнэ.
`lcs_01.tsv`: ALGORITHM/LOGARITHM → 7 (LGRITHM), GRAPH/TOMB → 0.

### 3.1 LCS-ээр файлын ялгаа гаргах (diff)
Хоёр файлын **мөр**-үүдийг тэмдэгт гэж үзээд LCS олбол ерөнхий мөрүүд хамгийн олон байна. Тиймээс
хасах (−) болон нэмэх (+) мөрийн нийт тоо **хамгийн бага** болно: |A| + |B| − 2·LCS.

Ялгааг эхнээс нь дарааллаар нь гаргахын тулд c[i][j]-г **сүүлүүдээр** (a[i..], b[j..])
тодорхойлов. i = j = 0-ээс эхлэн:
- aᵢ = bⱼ бол « » (хоёуланд байгаа),
- c[i+1][j] ≥ c[i][j+1] бол «−aᵢ» (aᵢ-г хасахад LCS буурахгүй),
- эс бөгөөс «+bⱼ».

Энэ нь Θ(mn) хугацаа, Θ(mn) санах ой хэрэглэнэ (сэргээхэд бүтэн хүснэгт хэрэгтэй).

Багшийн жишээ (`before.txt` → `after.txt`, ерөнхий мөр 6):

```text
 Алгоритмын зохиомж ба шинжилгээ
 Энэ баримт бичиг нь лабораторийн ажлын удирдамж юм.
 Оюутан хоёр хэл дээр код бичнэ.
+Сонгосон хэл улирлын турш өөрчлөгдөхгүй.
 Шалгалтын өгөгдлийг өөрчилж болохгүй.
 Хэмжилтийн үр дүнг тайланд хавсаргана.
-Тайланг markdown хэлбэрээр бичнэ.
 Merge request-ээр ажлаа илгээнэ.
-Багш хоёр даалгаврыг шалгана.
+Багш хоёр даалгаврыг хоёр хэл дээр шалгана.
+Дахин шалгуулах эрх нэг удаа олгогдоно.
```

Тест нь « » ба «−» мөрөөс A-г, « » ба «+» мөрөөс B-г яг сэргээж, ерөнхий мөрийн тоо LCS-ийн
урттай тэнцэхийг шалгадаг.

## Дүгнэлт

| Бодлого | Томьёо | Хугацаа | Санах ой |
| ------- | ------ | ------- | -------- |
| Ган саваа | r_n = max(pᵢ + r_{n−i}) | Θ(n²), давталт яг n(n+1)/2 | Θ(n) |
| Матрицын цуваа | m[i][j] = min(m[i][k] + m[k+1][j] + p_{i−1}p_k p_j) | Θ(n³) | Θ(n²) |
| LCS урт | c[i][j] = c[i−1][j−1]+1 эсвэл max(…) | Θ(mn) | Θ(n) (2 мөр) |
| LCS diff | сүүлийн c[i][j] | Θ(mn) | Θ(mn) |

Гурван бодлогын аль алинд нь бүх боломжийг шалгах арга экспоненциал (2ⁿ, Каталаны тоо, 2^min(m,n))
байдаг. Харин дэд бодлого бүрийг нэг удаа бодож хадгалснаар олон гишүүнт хугацаанд буулгав.
